Use these only after attempting the numbered exercises in [the lesson](../day_023_custom_hooks.md). They are specific to **Custom Hooks** and should unblock the next thought without replacing it.

## Hints

1. Read the short problem statement for custom hooks and say what the page or program should do.
2. Run the example without changes. If it works, write down what you see for a local toggle, data viewer, or form behavior with a named Hook API.
3. Point to the input and the line that changes the output. Do not try to explain the whole application at once.
4. Change one input for What is a custom Hook?. Keep every other line the same.
5. For Which logic belongs in a Hook?, try the normal case first. Then try one empty or bad value.
6. Make this mistake in a copy: Call a Hook conditionally or hide unrelated responsibilities in a Hook with an unclear contract.
7. Read the error or wrong result. Fix one line. Run the example again.
8. Use invented local data while you try Why must Hook names begin with use?.
9. Check the text, number, URL, or DOM element that the learner can actually see.
10. Use the same starter to build a local toggle, data viewer, or form behavior with a named Hook API. Do not add a new package.
11. A passing check only proves that check passed. Write one thing you did not test.
12. If a technical word is confusing, define it in your own simple sentence before using it.
