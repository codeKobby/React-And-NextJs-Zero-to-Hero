# Day 008 hints: Props and one-way data flow

Use these only after attempting the numbered exercises in [the lesson](../day_008_props_and_one_way_data_flow.md). They are specific to **Props and one-way data flow** and should unblock the next thought without replacing it.

## Hints

1. Read the short problem statement for props and one-way data flow and say what the page or program should do.
2. Run the example without changes. If it works, write down what you see for a reusable case card and button whose parent owns the data.
3. Point to the input and the line that changes the output. Do not try to explain the whole application at once.
4. Change one input for What are props?. Keep every other line the same.
5. For Why should a child not mutate props?, try the normal case first. Then try one empty or bad value.
6. Make this mistake in a copy: Treat read-only props as local mutable storage or create a second copy that can disagree with the owner.
7. Read the error or wrong result. Fix one line. Run the example again.
8. Use invented local data while you try How does data move down?.
9. Check the text, number, URL, or DOM element that the learner can actually see.
10. Use the same starter to build a reusable case card and button whose parent owns the data. Do not add a new package.
11. A passing check only proves that check passed. Write one thing you did not test.
12. If a technical word is confusing, define it in your own simple sentence before using it.
