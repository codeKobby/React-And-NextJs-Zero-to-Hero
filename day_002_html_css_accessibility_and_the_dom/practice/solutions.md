# Day 002 review guide: HTML, CSS, accessibility, and the DOM

Use this after attempting the the observation exercises in this lesson. It reviews the quality of the observation, not a single correct page.

## Review checkpoints

1. The heading has a meaningful level and is not chosen only for visual size.
2. The link and button are distinguished by navigation versus command intent.
3. The form control has a discoverable accessible name.
4. The keyboard path is recorded with focus order and a visible focus indication.
5. The DOM tag and attributes are copied from evidence rather than guessed from appearance.
6. The CSS-off observation separates structure and meaning from presentation.
7. The repeated elements have a clear parent and sibling relationship.
8. The status or error observation considers announcement and timing.
9. The proposed repair uses native semantics before custom ARIA.
10. The contrast or motion observation states what was checked and what remains uncertain.
11. The local starter review names a concrete next change without claiming the app is fully accessible.
12. The final note is reproducible, includes evidence, and identifies the next learning question.

## Self-assessment

Mark this ready when you can explain why React learners need browser and accessibility foundations, and when you can distinguish what you observed from what you have not yet tested.
