# Day 040 solution guide: Root app versus src/app

Use this guide only after attempting the numbered exercises in [the lesson](../day_040_root_app_versus_src_app.md). It reviews the decisions for **Root app versus src/app**; it is not a copied answer key.

## Review checkpoints

1. The learner can say what problem root app versus src/app solves in one or two simple sentences.
2. The example runs and the learner records the visible or returned result for a small App Router starter whose source, configuration, and public assets have named homes.
3. The learner can point to the input, the important line, and the output.
4. The learner changes one input for Why use src? and records the old and new result.
5. The learner tries a normal and an empty or bad value for When is root-level app simpler?.
6. The learner reproduces `Move app into src but leave an empty root app, then repair the ambiguous project.` and writes down the error or wrong result.
7. The learner fixes the smallest line and runs the normal case again.
8. The learner uses local invented data to show Which files stay at root?.
9. The test or check fails when the visible behavior is removed and passes after it is restored.
10. The learner builds a small App Router starter whose source, configuration, and public assets have named homes without exposing secrets or using real data.
11. The learner writes one thing the example does not prove about a real application.
12. The learner’s review note uses plain sentences and defines any technical word it needs.

## Self-assessment

Mark the work **ready** only when you can explain why the implementation works, reproduce the result from a clean checkout, and describe what it still does not cover. If your answer is “the framework does it,” return to the execution trace and identify the actual boundary where the behavior is decided.
