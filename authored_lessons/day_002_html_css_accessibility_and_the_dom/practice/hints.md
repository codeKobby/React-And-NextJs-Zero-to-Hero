# Day 002 hints: HTML, CSS, accessibility, and the DOM

Use these after attempting the the observation exercises in this lesson. They help you inspect rather than replace the work.

## Hints

1. Use the browser's outline or inspect the largest meaningful heading; visual size alone is not the answer.
2. A link navigates; a button performs a command. Test keyboard behavior rather than guessing from color.
3. Look for a `<label>`, matching `for`/`id`, or an accessible name exposed by the inspector.
4. Start at the browser address bar, press Tab, and record where focus moves.
5. Record the actual element name before discussing its CSS class.
6. CSS changes presentation; ask what structure and text remain when it is disabled.
7. Look for repeated siblings under one list, table, or region parent.
8. Check whether the status is text, has a role, and changes in a way assistive technology could notice.
9. Replace a clickable `div` with a native link or button according to the intended action.
10. Zoom, inspect computed colors, and look for a reduced-motion preference rather than relying on appearance alone.
11. Inspect `src/app/` output and name one semantic improvement you would make later.
12. Evidence is a URL or local path, observation, and limitation—not a claim that one inspection proves accessibility.
