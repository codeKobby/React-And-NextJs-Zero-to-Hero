# Day 057 solution guide: Deployment and environment configuration

Use this guide only after attempting the numbered exercises in [the lesson](../day_057_deployment_and_environment_configuration.md). It reviews the decisions for **Deployment and environment configuration**; it is not a copied answer key.

## Review checkpoints

1. The learner can say what problem deployment and environment configuration solves in one or two simple sentences.
2. The example runs and the learner records the visible or returned result for a portfolio-ready local case-management feature with architecture and evidence notes.
3. The learner can point to the input, the important line, and the output.
4. The learner changes one input for What is the production build? and records the old and new result.
5. The learner tries a normal and an empty or bad value for Which variables are public?.
6. The learner reproduces `Commit a secret in a local env file and repair the ignore and rotation plan.` and writes down the error or wrong result.
7. The learner fixes the smallest line and runs the normal case again.
8. The learner uses local invented data to show Where do secrets live?.
9. The test or check fails when the visible behavior is removed and passes after it is restored.
10. The learner builds a portfolio-ready local case-management feature with architecture and evidence notes without exposing secrets or using real data.
11. The learner writes one thing the example does not prove about a real application.
12. The learner’s review note uses plain sentences and defines any technical word it needs.

## Self-assessment

Mark the work **ready** only when you can explain why the implementation works, reproduce the result from a clean checkout, and describe what it still does not cover. If your answer is “the framework does it,” return to the execution trace and identify the actual boundary where the behavior is decided.
